# Evidence v3: realistic incident reports

Generated by `python scripts/build_evidence_v3.py` from the frozen
`evaluation-v2-20261125` release. Run `python scripts/build_evidence_v3.py --check` to confirm these
files match a fresh rebuild.

## What is different from v2

| Change | Why |
|---|---|
| Sites have a town name, a site code, district and lat/lon in the Western Province | Reports refer to places and codes, not internal IDs, so agents must resolve aliases. The map uses these coordinates. |
| Every labelled report is rewritten from its v2 label as an NMS alarm, road bulletin, field WhatsApp message or duty-manager note | The regex template parser no longer applies; extraction quality now changes the plan. |
| 2–4 distractor reports per case: customer complaints, an irrelevant utility notice, a low-authority rumour and, in about half the cases, a prompt-injection message | Tests precision, authority handling and injection resistance. |

Unchanged: topology, roads, crews, generators, actions, services, policy, report IDs,
source types, timestamps, hidden truth and future events. v2 claim labels remain the
extraction labels; `distractor_reports` in each truth file lists reports that carry
no operational fact.

## Limits

- Places are real towns; **sites, codes and faults are fictional**. Not tower locations or coverage.
- Wording comes from fixed phrase banks (seeded), so it is more varied than v2 but still synthetic.
- Script-generated and not yet independently human-reviewed. Development cases may be used for tuning;
  `candidate_evaluation` (EVAL2) cases must not be tuned on.
